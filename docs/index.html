THE KEY CONNECTION

The backward map describes a desired state in task space. The forward map predicts discounted future features. Their inner product with a prompt gives the actor an objective. The motion dataset and auxiliary penalties shape which behaviors that actor learns to produce.

A policy learns from two streams.

Online interaction supplies transitions and physical consequences. Retargeted LAFAN clips supply state-only examples and task embeddings. There is no behavior-cloning loss against expert action labels in this training path. “Unsupervised” still includes a motion prior and hand-designed physical penalties.

02 / EXECUTION

One iteration, end to end.

FIRST, NAME THE THINGS

A prompt is one concrete z vector.

It is the actor’s task input: 256 numbers describing what to try to achieve. The reference rollout holds one vector per environment, so the variable z is a batch shaped [1024, 256]. Row 7 is environment 7’s current prompt.

Observation + history“What is the robot doing now?”
Prompt z“What should it try to do?”

For example, encoding a desired crouching pose with B gives a task direction that asks the policy to reach that pose. A random z is also a valid task input, but it has no assigned human-readable label or guaranteed skill. The policy’s weights determine how well it can carry out either request.

context in the trainer is this z batch. history_context names a separate optional history encoding. Rollout means using the policy to collect physical experience; a learning update changes networks using stored experience.

The reference recipe advances 1024 environments together. One vector step adds 1024 transitions. After warm-up, each vector step triggers 16 agent updates, each with an online batch and an expert batch of 1024 samples.

CODE NOTES

Open a note. Read a few lines, then their meaning.

What happens before the loop?

Workspace seeds RNGs, creates one simulator environment, derives Gym observation spaces, creates or restores the agent and optimizers, sets up evaluation and W&B, and writes the config. Expert trajectories are reconstructed from the motion library and put in a trajectory slicer. Online replay starts empty or loads from the checkpoint. The initial evaluation runs at step zero for recipes with evaluation enabled.

The single simulator instance is shared with training evaluation. Evaluation changes its state, so training resets afterward. The replay transition before the evaluation cut is marked truncated. This matters when reasoning about trajectory boundaries.

Read the class hierarchy without getting lost

FBcprAuxAgent → FBcprAgent → FBAgent. The auxiliary agent owns the actual update order and combined actor loss. It inherits discriminator training and the style critic from FB-CPR, and inherits FB representation learning and prompt rollout logic from FB. Follow individual method calls across these three files rather than reading each as a separate algorithm.

FBcprAuxModel → FBcprModel → FBModel stores the corresponding networks. Public model methods normalize observations and serve inference. Underscored network methods in the training update receive already-normalized inputs. Normalizing twice changes the problem.

03 / INPUTS & ASYMMETRY

The actor does not see what the critics see.

The simulator produces a rich observation dictionary. Each network's DictInputFilterConfig chooses its own keys. Privileged information existing in the replay does not mean the deployed policy consumes it.

Widths are derived from the current 29-DoF hard-waist robot, its 30 bodies + 1 extended head, and the configured history. Verify them again when changing robot/observations. See observation YAML, the wrapper and network filters.

Two kinds of “history”

seq_length=8 controls expert sequence sampling and prompt averaging. history_actor is a flattened 4-step input. The optional context_length mechanism is a separate path and is disabled in this recipe. There is no active recurrent memory encoder in the default path.

Actions are targets, not torques

The actor emits 29 normalized actions. The environment maps them to offsets around the nominal pose, scales them and uses PD control to produce torques. The hard-waist robot name denotes a configured robot variant; inspect its gains and asset rather than assuming that “29 DoF” means identical hardware/control settings across forks.

Expert encoding and reset boundaries

The expert loader reconstructs proprioception and privileged observations from motion poses and velocities. It sets expert actions to zeros; B and D do not use those action fields. Online normalizer statistics are updated on current and next online observations, then expert and online observations are normalized with those statistics under evaluation mode.

make_transition() stores explicit physical successors. When the environment autoresets, the successor for the replay must be the physical state before reset, not the new episode's initial state. terminated stops bootstrap; timeout truncated separates sequences but still allows bootstrap. That is why the agent uses discount * ~terminated, not discount * ~done.

01 / DISCRIMINATORUPDATES D ONLY

Distinguish motion states from online behavior.

ℓD = E[softplus(−logitexpert) + softplus(logitonline)] + 10 GP

expert_z is a detached average of backward embeddings over an 8-frame expert sequence, projected to the latent sphere and repeated across that sequence. The negative example uses the rollout's saved z. The discriminator update happens before online z relabeling.

The gradient penalty interpolates observations and latents, then penalizes deviation of the joint gradient norm from 1. The implementation calls it WGAN GP, while its classification objective is binary cross-entropy. This is a regularizer, not a Wasserstein objective.

expert_loss    = -F.logsigmoid(expert_logits)
unlabeled_loss = F.softplus(unlabeled_logits)
loss = (expert_loss + unlabeled_loss).mean() + 10 * wgan_gp

Watch: disc_expert_loss, disc_train_loss, disc_wgan_gp_loss. Chance BCE is a reference point, not a success criterion: a discriminator can be confused because the policy improved or because learning collapsed.

02 / REPRESENTATIONUPDATES F AND B

Fit future occupancy without task reward labels.

Mkij = Fk(xi, ai, zi)ᵀ B(s′j)
Δkij = Mkij − δi M̄ij
ℓFB = ½ Σk,i≠j Δ² / [n(n−1)] − Σk meani Δkii + 100 ℓortho

x here denotes the critic's filtered observation/history. Target F uses successor observations and an action sampled from the current actor; target B encodes the candidate successor states. Two target forward heads are combined with the uncertainty penalty. The default FB penalty is zero, so that target is their mean.

Every row is paired with every column in a batch. Off-diagonal elements fit the Bellman recursion for arbitrary candidate states. Diagonal elements represent the observed immediate successor and supply the linear attraction term. This is why the loss is a [2, 1024, 1024] matrix calculation, not a conventional scalar reward TD error.

Ms   = Fs @ B.T                         # [2, batch, batch]
diff = Ms - discount * target_M
fb_offdiag = 0.5 * (diff * off_diag).pow(2).sum() / off_diag_sum
fb_diag = -diff.diagonal(dim1=1, dim2=2).mean() * 2
fb_loss = fb_offdiag + fb_diag + ortho_coef * orth_loss

Backward geometry: with G = B @ B.T, the code uses orth_loss = 0.5 * offdiag(G²).sum()/[n(n−1)] − mean(diag(G)). The normalization layer fixes B's output norm to √d. Minimized total loss need not approach zero. The optional scalar q_loss is disabled by q_loss_coef=0.

Watch: fb_offdiag, fb_diag, orth_loss_offdiag, B_norm, z_norm, values and evaluation together. A norm near 16 is largely imposed by construction; it is weak evidence against directional collapse.

03 / STYLE VALUEUPDATES QD ONLY

Give the actor the long-term value of looking human-like.

rD = log D − log(1 − D)
yD = rD + δ · [mean(Q̄D) − 0.5 uncertainty(Q̄D)]
ℓQD = ½ K · MSE(QD, yD)

The reward is the log-odds of the clamped sigmoid discriminator output. update_critic() computes it under no_grad(); this critic update does not optimize D. A separate target critic stabilizes the bootstrapped future estimate.

With two heads, the uncertainty is their absolute difference. Mean minus 0.5 times that difference equals the smaller head. Do not interpret this heuristic as a calibrated confidence interval.

Watch: critic_loss, mean_disc_reward, unc_Q, Q_discriminator. Growing Q with degrading evaluation suggests value extrapolation or scale drift; a falling critic MSE alone does not establish a useful policy.

04 / AUXILIARY VALUEUPDATES QR ONLY

Estimate the future cost of physically undesirable behavior.

rR = normalize(Σk weightk · raw_penaltyk)
yR = rR + δ · pessimistic(Q̄R)
ℓQR = ½ K · MSE(QR, yR)

The environment exposes info['aux_rewards'] before reward scales or curriculum. The agent applies its own aux_rewards_scaling dictionary. These are the effective weights for QR; editing only the YAML's aggregate environment reward is not the same intervention.

The default reward normalizer scales by a running standard deviation without translating the mean. Penalty values therefore retain their sign while their scale changes. This affects the auxiliary critic's numerical values over training.

05 / POLICYUPDATES π ONLY

Turn three value estimates into one action gradient.

QFB = pessimistic(F(x, π(oH,z),z)ᵀz)
w = stop_gradient(mean |QFB|)
ℓπ = −mean QFB − 0.05 w mean QD − 0.02 w mean QR

The actor samples an action with fixed standard deviation 0.05 and clipped exploration noise. Gradients pass through each critic's action input into the actor. The step updates the actor optimizer; its objective uses pessimistic values from each twin ensemble.

scale_reg=true multiplies both regularizers by the detached average absolute FB value. Thus “0.05 style” and “0.02 auxiliary” do not have fixed influence across training. A growing FB value scale also grows those effective weights. This implementation detail is useful when comparing curve magnitudes.

weight = Q_fb.abs().mean().detach()
actor_loss = (-Q_fb.mean()
              - reg_coeff * weight * Q_discriminator.mean()
              - reg_coeff_aux * weight * Q_aux.mean())

After all updates, target F/B parameters move toward current parameters with τ=0.01; style and auxiliary critic targets use τ=0.005. B's learning rate is 1e−5, while F, actor and the two critics use 3e−4. The backward embedding and its meaning therefore evolve along with the policy.

Watch: Q_fb, Q_discriminator, Q_aux and evaluation. An increasingly negative actor loss is not itself convergence.

05 / TASK DISTRIBUTION

There is more than one distribution over z.

“Sample a latent” hides several mechanisms. Distinguish the minibatch's training tasks, the rollout tasks that collect replay, and the tasks inferred at test time.

60% expert sequence
20% online goal
20% random sphere

sample_mixed_z() constructs this mixture. Then 80% of online samples are relabeled with new z; the remainder retain their behavior prompt. The transition stays the same. Relabeling trains the conditional value/policy on alternate tasks using off-policy data.

During rollout, prompts refresh every 100 control steps. A separate mechanism assigns 50% of environments expert-derived prompt sequences over 250 steps. These are policy rollouts prompted by expert states, not expert action playback. This is why setting the style coefficient to zero does not remove every expert influence.

Motion prioritization is a feedback loop

At scheduled tracking evaluations, per-motion EMD becomes a priority: 2 ** (clamp(emd, 0.5, 2.0) * 2.0) in the native reference config. It updates both motion initialization weights and expert slicer priorities. Hard-to-track clips get more sampling weight, with bounded range. Changing evaluation cadence therefore changes more than logging overhead.

The evaluator uses the motion library currently configured for training, so the prioritized clips are training clips. Keep an independent fixed evaluation protocol for comparisons. The smoke preset disables evaluation and prioritization to make the first execution short.

07 / COMPUTE

Know what “a step” buys you.

The training loop counts aggregate environment transitions. Distinguish gradient updates per vector step from updates per individual transition. “UTD = 16” without this denominator is ambiguous.

0.015625gradient updates / new transition
16sampled transitions / new transition
16updates / vector step (average)

Reference recipe: one update trigger per vector step.

Sample reuse above is an expected sample count, not the number of unique replay transitions seen. It excludes expert samples. Each agent update includes multiple optimizer steps. Batch all-pairs FB matrices scale quadratically with batch size, while replay storage scales linearly with capacity.

Why host replay on L40S?

The default observation dictionary has about 928 floats. Current + next observations, actions, z, qpos/qvel and penalties make the 5.12M replay roughly 44 GiB of float payload, before overhead. It competes with model weights, targets, gradients, optimizer states, activations and PhysX if placed on the GPU.

L40S has 48 GB and RT cores. CPU replay is a sensible fit hypothesis; only a real run can establish remaining memory and transfer cost. Start with 128 GB host RAM and inspect peak usage. Checkpointing temporarily keeps old and new copies on disk.

GPU compatibility is separate from VRAM.

NVIDIA lists A100/H100 GPUs without RT cores as unsupported for Isaac Sim. We select L40S as the first path. A high-VRAM compute card is not automatically a supported simulator card. The container pins Isaac Sim 4.5 + Isaac Lab 2.0.2; do not transplant SceneGMT's newer simulator image.

Requesting multiple GPUs will not distribute this Workspace. The repository links a separate distributed implementation, which is a different experimental path.

Hardware sources: NVIDIA requirements · L40S specifications. Memory above is a source-derived estimate, not a measured peak.

08 / DIAGNOSIS

Convergence is a behavior claim.

Save the initial evaluation as a reference. Compare fixed snapshots at equal transition budgets, on the same motion file, initialization, seeds, randomization, noise and prompt horizon. Learning moves the policy, data distribution, representation, discriminator and normalizer simultaneously.

QuestionInspect in W&BWhat it can tell you
Is motion matching improving?eval/humanoidverse_tracking_eval/emdDistributional joint-position matching. It ignores temporal correspondence, so pair with aligned error and videos.
Is timing/pose tracking improving?.../joint_angle_l2_radTime-averaged L2 error across all joint angles, in radians. This is not Cartesian MPJPE.
Is motion becoming smoother?.../joint_velocity_l2_rad_s, .../joint_acceleration_l2_rad_s2Aligned joint derivative errors; very short clips omit unavailable derivatives.
Does the representation remain useful?train/fb_offdiag, train/fb_diag, train/orth_lossBellman fit and embedding geometry. Their absolute scale is not a task score.
Is the style prior saturating?train/disc_expert_loss, train/disc_train_loss, train/mean_disc_rewardSeparation, policy reward and imbalance; inspect alongside behavior diversity.
Are violations decreasing?train/aux_rew/*, train/mean_aux_rewardRaw violation statistics versus a changing normalized weighted sum.
Are values diverging?train/Q_fb, train/Q_discriminator, train/Q_aux, uncertainty metricsValue scale drift, especially when evaluation stagnates or worsens.
How expensive is progress?train/FPS, elapsed time, external RAM/VRAM samplingMeasure after compile warm-up. Native FPS windows include some evaluation/checkpoint overhead.
Do not select a run from one curve. A useful checkpoint should improve fixed-protocol tracking, produce plausible diverse prompt videos, and avoid increasing violations. Replicate conclusions across training seeds. Variation across motions and inference samples is a different source of uncertainty from training seeds.
Common observations and the next diagnostic
  • EMD improves but aligned error does not: inspect temporal lag, initialization and prompt lookahead. EMD can reward a matching pose distribution in a different order.
  • Auxiliary score improves but policy barely moves: inspect raw penalties and diversity; low movement can reduce action/contact penalties without learning the desired skills.
  • D becomes perfect quickly: verify online/expert observation conventions and scales before changing learning rates.
  • Losses are finite but policy quality plateaus: compare coverage, prompt mixture and individual motion failures. The optimization target can be fit on a narrow replay distribution.
  • Checkpoint fails or training runs out of memory: separate replay placement, optimizer/activation VRAM, expert preload and checkpoint host/disk peaks.
  • Resumed W&B curves show gaps: the training checkpoint can lag logged steps; offline segments do not resume seamlessly. Check saved step and logging run identity.
09 / YOUR FIRST STUDY

Answer one question
with each experiment.

  1. Can the complete loop execute?

    Preflight → Isaac startup → 4096-step smoke. Verify finite updates, saved replay/checkpoint and an offline W&B file. Then test online logging and resume from 4096 to 8192.

    Outcome: working plumbing

  2. Can the native model learn on the selected hardware?

    Run the 10.24M pilot on L40S. Measure memory, compile cost, FPS, eval overhead, disk size and initial learning direction. Keep full reference networks; label reduced replay clearly.

    Outcome: feasible learning pilot

  3. What does the early representation actually control?

    Freeze a snapshot while training is stopped. Numerical tracking on full LAFAN, three evaluation seeds, then videos for tracking, goal-reaching and reward prompts. Look at failures, not only good clips.

    Outcome: interpretable early behavior

  4. Does longer training improve the same policy family?

    New reference run with full CPU replay; inspect 50M/100M and continue toward the chosen 192M paper budget or 384M native budget. Match evaluation protocol and keep timed snapshots.

    Outcome: a baseline learning curve

  5. Which conclusions survive random seeds?

    Repeat the fixed recipe with three training seeds. Compare equal transition budgets and wall-clock cost. Do this before attributing a small gain to a changed coefficient.

    Outcome: uncertainty you can interpret

  6. What do the regularizers contribute?

    Matched runs with auxiliary actor weight zero, then style actor weight zero. Critics still train; expert prompts still shape the style ablation. Inspect violations and diversity as well as tracking.

    Outcome: mechanism-level evidence

  7. How do robustness and latent capacity change behavior?

    No-DR training versus baseline, evaluated both nominally and with DR. Then z=64 versus z=256. Keep sensor noise explicit. Each architectural or distribution change starts a new run.

    Outcome: targeted ablations

  8. Is an inference failure really a training failure?

    On one frozen model/replay, vary reward inference samples and repeat prompt estimation. Add a quantitative task-return evaluator before selecting by reward score. Try pose-prompt interpolation, then consider latent CEM adaptation.

    Outcome: separate representation from inference

A thin layer around the original trainer.

The launcher loads default_train_config(), merges a small JSON preset and optional overrides, validates with the repository's Pydantic schema, then calls cfg.build().train(). It records data/lock hashes and software/commit metadata without dumping the environment.

  --config experiments/ablations/paper_budget.json --seed 4728

Change resources in cluster/pyproject.toml or pass scheduler flags before --. Pass experiment arguments after --. Use --set agent.train.num_typo=... and validation will reject it. Lists in JSON overrides replace lists; --hydra key=value replaces an environment override with the same key.

Keep authentication outside the experiment.

Team glen-berseth, project bfm-zero. The cluster defaults to online logging with the modern W&B image. Choose offline mode explicitly to log locally without a key. Online jobs use external ~/.netrc through a read-only mount, or a scheduler-injected key. No key goes into a config, image, launch command argument or provenance record.

The project UI and API have different URLs. The configured API is https://api.forge.coreweave.com; W&B 0.27.1 passed an online write check using the external credential mount. The base image has the older SDK and rejects new-format keys.

Keep results stable while code evolves.

The job binds BFM_CODE_DIR (your normal home checkout) directly at /workspace/bfm-zero. Public motion data and persistent scratch outputs have separate mounts. Keep the checkout at the experiment's version while training runs.

cluv needs reviewed commits and can push them. The image passed CPU regression tests, CUDA physics stepping and online logging checks. These validate setup; policy quality still needs a completed training run and evaluation.
